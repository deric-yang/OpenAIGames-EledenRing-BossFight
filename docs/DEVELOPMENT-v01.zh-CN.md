# 恸哭沙丘：首轮开发记录

2026-09-27。本文件记录本轮实际实现；早期 HANDOFF 是历史快照，范围冲突时以用户本轮要求为准。

## 最新美术约定

- 玩家：**银灰钢甲、炭灰织物**。不再采用早期总设定图里的金甲方案。
- Boss：暗铁、旧金雕饰、暗红织物；按后续反馈改为**单手持用的一把厚重直刃巨剑**，暂名 Great Enemy。最新资产修订见 ASSETS-v02.zh-CN.md。
- 场景：广阔沙丘、战争残骸、零星余火；远方黄金巨树与半透明帷幔。
- 首批 5 件 Tripo 静态原件已生成并下载；原件不等于已经减面、绑骨或接入游戏的运行件。
- Boss 动作等待用户选片；没有新增 Boss 技能或用程序动作替代正式动画。

## 已实现

- 可共用的 VitalBar：红色生命条、绿色耐力条、旧金符文端点、细边框与污渍。
- 实际生命立即变化，虚血停留约 1 秒后追赶；连续命中总停留设上限，虚血不回复生命。
- 玩家攻击消耗 18 耐力、翻滚 26、疾跑每秒 18；停止消耗 0.65 秒后每秒恢复 28。
- 耐力不足拒绝动作；疾跑耗尽后需松开疾跑键且恢复到 15 才能重新疾跑。
- 翻滚取消当前白盒攻击；复活恢复耐力并清理虚血历史。
- 出生／复活时中央显示“恸哭沙丘”；不再用地点卡展示阶段切换。
- 胜利中央金字 Great Enemy Defeated，黑色噪声烟雾背景；2.5 秒开始消散、3.2 秒完全结束。
- 下方奖励卡 Great Enemy's Weapon，约 0.55 秒后出现、6 秒结束；当前图标已由双刀改成单把巨剑，仍为程序绘制占位。
- 胜利隐藏 Boss 血条，复活恢复；奖励与地点动画互不残留。
- 插剑火堆程序模型与动态火焰，位于玩家出生点旁；此项为功能占位，并非 Tripo 成品。
- UI 预览场：1 玩家受伤、2 耐力、3 Boss 受伤、4 复活、5 胜利、6 连续受伤，也可点击按钮。
- Cormorant Garamond 与 Noto Serif SC 中文子集随项目打包，避免 Web 缺系统字体。
- Web 导出预设及 4.7.2 Web 模板已配置，首个 WebGL2 白盒构建已真实打开并显示。

## 本地入口

- `启动UI预览.command`：正式 HUD 的独立交互预览，背景为概念图，不是 3D 渲染。
- `启动游戏.command`：白盒游戏与正式 HUD。
- Web：构建目录 `builds/web`，仅对此目录启动静态服务，**不要把项目根目录作为静态站点公开**。
- Web 游戏：`http://127.0.0.1:8093/`；UI 预览：`http://127.0.0.1:8093/?ui=1`。

## 首批 Tripo 任务

新管线 `scripts/tripo/produce.mjs` 使用 `production-v01.json`；旧 `generate.py` 保留用于已有离线回归，不用于本轮生成。

先生成 player_silver_v01，检查角色拓扑、材质和可绑定性后再扩充：

| ID | 输入 | 后处理目标 |
| --- | --- | --- |
| player_silver_v01 | 银灰骑士单体 A-pose 图 | 绑骨、刀剑三连／翻滚／受击测试 |
| great_enemy_body_v01 | 独立中立姿势提示词 | 保持连续人体骨架；大型装饰后挂 |
| great_enemy_blade_v01 | 单把巨刀提示词 | 统一握点、缩放、派生双持实例 |
| war_relic_cluster_v01 | 紧凑残骸堆提示词 | 减面、碰撞代理、实例变体 |
| golden_tree_v01 | 巨树主形提示词 | 主枝轮廓、金裂隙、远景 LOD |

原件 → Blender 加工 → 运行件分离，保存任务 ID、请求、文件哈希与实测面数。准备完成不等于已提交或已生成。

已核对官方 v3 文档：
- https://developers.tripo3d.ai/en/docs/quick-start
- https://developers.tripo3d.ai/en/docs/generation-image-to-model
- https://developers.tripo3d.ai/en/docs/files
- https://developers.tripo3d.ai/en/models/v3-1
- https://docs.tripo3d.ai/zh/other/support-faq.html

本机直连存在 DNS／TLS 问题；系统 PAC 路由配合系统受信任 CA 可以访问国际接口。TLS 校验始终开启。
后续用户提供有效 API Key，鉴权与在线生成已成功。首批 5 件合计消耗 260 credits，生成前余额 1375，生成后余额 1115、冻结 0。凭据仅在本地忽略文件中保存，静态服务器只服务 builds/web。
